# V2 听写技术暂缓升级边界（2026-10-30）

V2 的 `deferLearning` 对当前听写题将该日该词的 `learning_day_words.deferred` 设为 1，将该题 `answered_at` 置为暂缓时间（不生成 `answer_id`、结果或答题日志），并将词的 `due` 设为次日。字段组合可作为迁移前的线索；单独的已关闭状态并不能说明发生过技术暂缓。

原有 V2 到 V3 升级把已关闭题记为 `legacy_verified` 的 exposure，并重置当天条目的 deferred；不会产生 `technical_defer` 事件。`test/audio-cooldown-summary.test.ts` 用隔离数据库复现：升级前暂缓且无答题，升级后无答题、无复习日志、无技术暂缓事件。当时未修改升级逻辑或推断旧事件；具体后续修复见下。

当时拟定的兼容方案：在升级前保留原始 day-word 和 issue 身份、字段与升级时间，仅对唯一匹配的无答案听写暂缓保守记录可追溯的旧技术事件；保留可回退的迁移记录，不从关闭状态推断。已经升级的数据，当天 deferred 已被重置，证据未必完整；旧日字段即使保留也需结合关联题核验。原有连续技术失败次数和时间无法一概恢复，不应凭空构造或将曝光自动解释为失败。任何方案需要针对旧数据、多题、重复迁移与恢复单独验证。

## 后续实施

首次激活 V3 时，迁移事务仅识别同时满足以下条件的最后一条听写：同词同日的 V2 `deferred=1`，唯一已关闭但没有答案和结果的听写题，题目/关闭时间有效且关闭时间在该上海自然日、不晚于迁移时刻，且该词此后没有其他听写题。符合时保留原 issue ID 和关闭时间，记为 `legacy_verified` 技术暂缓，不把未经提示的技术暂缓误记为答案曝光。已经提示的题仍保留提示暴露及相应真实证据。模糊、多候选、时间异常及后续曾有听写的记录均不推断；不回溯更改已完成 V3 升级的库。仅以最新可识别事件起算，不臆造之前的连续失败次数。技术暂缓既不计入正确率，也不单独作为词汇接触或掌握证据。

隔离数据库测试覆盖原计划位置、旧答题日志及重放、无答题/错误率、唯一与歧义案例、未来时间、重复激活以及 SQL.js 恢复后的冷却和跨日。新版本不更改旧 issue、答案和复习日志；迁移既有的原字段快照仍用于追溯。
