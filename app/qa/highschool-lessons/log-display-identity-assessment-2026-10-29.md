# Log / log 分离身份与展示修正评估

教材选择性必修四 Unit 3 词表 p.108 写普通名词 `log`。现行 catalog 存在两个 entry key：`Log` 在高中 Unit 3，`log` 在四级、考研、托福、雅思和 GRE。二者有独立的本地 word ID，用户可能各自有学习进度、错题、发题与事件；词头相似不足以证明可以合并。该报告不修改用户数据。

`words` 表约束为 `UNIQUE(source,headword)`，两个条目均可能以 `source='vocabulary'` 存储；直接把旧 `Log` 字段更新为 `log` 会与考试词条冲突。更改 source 会影响导入身份与后续更新，不能当成纯显示操作。导入映射 `vocabulary_entry_map` 的稳定 `entry_key='Log'` 可将高中身份映射到每台设备自身 ID，不应使用固定 ID。内容 3947.json 词头为 `Log`，服务端及离线运行时按词头和 ID 严格校验，直接显示改名后可能失去讲解。

一个可行的后续工程方向是独立保留内部 identity/headword，只给通过 entry key 精确识别的目标设置显示字段 `log`：分别覆盖词书和搜索、详情、学习题面和反馈、旧题流程、错词统计及离线，音频与讲解仍按内部身份查找，公开响应和前端校验需有明确的内部/展示字段契约；不对所有字符串 `Log` 全局小写。测试需在两实体共存且双方拥有不同学习历史时验证所有身份不变；分别验证旧题发出后升级、重复提交，新老设备的不同 ID、映射冲突、离线安装与升级和讲解获取。决定此方案前，还应审查额外内存/查询开销和其他来源拥有同名词的情况。

当前未对 Log 做任何代码或数据修正；单一客户端页面小写无法证明所有入口一致，也无法证明讲解或离线升级安全。

## 首阶段实现（2026-10-29）

已增加独立显示投影，只有 `vocabulary_entry_map` 中 key 为 `Log` 的设备本地 word ID、且原始词头仍为 `Log`，才展示 `log`；内部存储、两个词条的用户数据和作答判分不变。首阶段接入搜索、选择 Unit 浏览、详情、学习单词本、V2/V3 当前题与结果、在线和离线讲解。另有身份限定的 highschool-log keyed 资源，避免依赖固定 3947 ID 或让不同来源同名词错误获取讲解；资源按原内部词头校验，响应时再投影。

定向测试包含两身份共存、其他来源 `Log` 不改、所选 Unit、在线与离线不同 ID 讲解、资源打包、V2/V3 题目及重复提交和离线当前题；全量 1407 项测试与 typecheck 通过。已继续覆盖家长统计、错词、错词练习和旧选择题；测试覆盖新发及恢复题与反馈。浏览器和移动构建验收仍待完成，其他未经专项验收的入口不作全面保证。该实现不合并两词的历史，不改变 catalog 中的两个身份。
