# 在线词库版本回退保护

新服务主入口对已存在数据库在任何 `openDb` 写入和迁移备份前读取只读快照，比对当前捆绑词库与数据库 `catalog_version`。数据库版本更新则中止启动并提示使用新版；版本值非法也拒绝写入。`installBundledVocabulary` 再次检查，避免其他调用方将较低版本写入。版本相同的重装及正常递增升级仍可运行。

成功加载新版词库的在线数据库还设置 SQLite 触发器 `vocabulary_catalog_version_monotonic`，拒绝对版本标记执行数字降级更新。正常服务启动在安装缺失触发器前会创建已有的版本迁移备份；触发器与完整词库导入同事务写入。该触发器作为历史二进制的额外防线：并不提供只读快照启动保护，也不覆盖从未由带该机制版本初始化的库；不能阻止旧程序先执行其他代码、更改统计或先创建备份，不能保证任意旧二进制不删除或绕过触发器。回退应用应先保留独立备份并使用独立数据库，不应以此触发器作为允许原地降级的依据。

2026-10-30 从 git `6978cf98` 导出原样 v158 server 与 catalog 至隔离 `/tmp/xiaobei-v158-audit`；以当前代码在另一临时数据库安装 v159 和真实触发器，再由老版本 `openDb` 加 `installBundledVocabulary` 执行。老版本在其事务末尾更新版本时被 SQLite 阻断并报“当前程序的词库版本较旧”；catalog_version 仍为 159，SQL 逻辑 dump SHA-256 前后均为 `c7d0bce6604b1c63e51ffb0f634ff698cde20c9909cb77c3b8aa60f7b81ea529`。这是该隔离空用户库的实测，不证明所有已有数据不发生旧启动前副作用；该测试未修改用户学习库。

旧离线包的 `prepareVocabularyDatabase` 已按 `>=` 跳过较旧目录并保留数据库版本；这只说明不回写旧 catalog，不证明旧 APK 录音、界面和新数据库的语义一致。旧包仍应避免直接使用新版本个人学习数据。测试包含不同来源与手动内容的现有升级流程，不替代旧程序全状态兼容性验证。
