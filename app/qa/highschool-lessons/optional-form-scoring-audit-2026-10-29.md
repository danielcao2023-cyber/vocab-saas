# 高中括号及可选形式出题审计

只读检查 catalog version 135：逐一筛选至少一个 `pep2019-` membership 的 2730 个唯一词条，查找英文/中文括号及斜杠，命中唯一词头 `from (then) on`，key 为 `from on`，必修二 Unit 5 position 381。它与完整词条 `from then on`（同一 Unit position 382）分别有身份、卡片及学习记录；`from now on` 当前不在 catalog。扫描仅涵盖词头中的显式括号或斜杠，不代表教材中所有省略号或其他语义重叠形式已穷尽。

`acceptedSpellings('from (then) on')` 目前返回 `['from on','then']`：把括号中的 then 单独当作候选答案，同时未生成完整 `from then on`。因此若仅调用底层通用函数，对该词有误收与误拒；然而 `hasDictionaryPlaceholder` 已将该教材词头加入只认词保护。V2/V3 排题和旧的 `checkSpelling` 禁止对该条发起新的拼写/听写；V2/V3 会在恢复或提交旧未答拼写题时保护该条，已答重放按原结果处理。因此这里不是断言目前正常交互中仍会错判，而是存在危险的底层答案集和日后解除保护会暴露的问题。完整词条 `acceptedSpellings('from then on')` 返回完整短语，未命中只认词保护。

两条独立 Unit 词条都在每日候选内；尽管教材的完整自然表达在这里重叠，系统按不同 word_id 排题并各自记录，因此可能重复测试，具体是否在同一天出现取决于调度和复习状态。`keep in mind` 与 `keep ... in mind`、`dress up` 与 `dress sb. up` 也是可选成分被拆出的相邻词条；前者已有保护但这些表达并非完全同形，带对象和无对象的使用条件不同，须按具体语境处理，不能机械归并。

建议顺序：

1. 保持当前只认词保护，针对 `from (then) on` 设置局部解析或显式答案元数据（例如完整 `from then on`，需先确定教材括号语义与将来题型），明确拒绝单独 `then`、不完整 `from on`。不要全局把所有括号当可选拼接，已有其他词库的括注规则可能不同；在完成覆盖测试前不要解除保护。
2. 先设计同义候选分组/每日去重，使相同学习目标在当前任务只出现一次；两个 word_id 的历史、成绩和已有复习时间原样保留；明确哪一项被安排、另一项何时被检查，防止无限饥饿或把一项的证据误记为另一项。题面含具体对象时需独立语境设计。
3. 对旧未答题先以当前机制安全关闭/重发，不能将现有 Issue 改成不同词 ID；对已提交 answerId 重放保留当时结果且不重复生成复习记录。未来如果确需合并身份，需分别迁移本机两组 cards、events、错题、跨词书 membership、历史统计和进行中题目，提供备份、冲突处理和可回滚方案，不采用直接删词或外键覆盖。
4. 回归分别验证 V2/V3 的新发题、旧未答题和重复提交，旧单卡接口和离线运行，正常完整短语仍可拼写听写，并核实同日去重不吞掉后续复习。既往快照 `highschool-placeholder-question-audit-2026-10-29.md` 中“未受保护”的表述是修复前状态，不代表当前情况。

## 已有选词与跨日行为（只读设计）

- V3 `evidence-engine.ts` 的 `selection` 先从当前所选词书/Unit 得到按 word_id 独立的集合；把前一天未完成或 capability 到期的词按未完成、priority、due、id 排序，然后截取每日上限，再由 `composeFresh` 填充未引入的词。现在没有语义组去重，因此这两个同 Unit ID 可能同时进入同一天。独立卡片、事件和 due 均不会因另一个词的作答自动更新。`learning_day_words` 以 day+word_id 保存已开启日计划，重进继续使用；跨日 `unfinished` 会把未完成项提前，不能简单将被去重项写成 done 或篡改 due。
- V2 `selection.ts` 的 `selectDaily` 也按独立 word_id 排到期和未完成，然后填充新词，同样没有组去重。`selectedWordIds` 只返回当前范围，因此任何组处理都应首先尊重当日有效词书与 Unit，不能从范围外额外加词。

建议**只在生成未来新日计划之前进行候选组去重**，不修改过去或已经开始的当天计划。首组显式配置为稳定 entry keys `from on` 与 `from then on`，每次通过 `vocabulary_entry_map` 解析本设备 ID；若缺成员、映射歧义或成员已非预期教材表达，回退原选择并记录问题，绝不以固定 seed ID 识别。适用范围先限定两个成员都属于当前有效所选范围，避免跨词书误排或无法访问的项。

将同组候选归并为一个每日计划席位，**在截取每日上限之前**去重并继续从后续候选补位，避免承诺 40 词时实际无故减少；未被选中者的学习状态和到期时间原样保留，不算完成、不产生事件。到期词优先于未接触词；两者都到期时先选择较久到期/未完成者，但如果一成员连续失败一直保持最早 due，仅靠 earliest due 会饿死另一成员；需要显式公平规则：若另一个成员仍有符合条件的未完成或到期任务，下一次同组进入新日计划时优先安排另一成员，再在公平条件允许时按原优先级。公平信息应从历史 `learning_day_words` 推导并定义清楚：仅对有效计划、当前选择范围的成员计数；用户主动暂缓、不学习或切换范围时，明确不伪造成功；长期选择不同范围时仍应按该范围可选成员安排。未接触的完整词条何时补入也需显式规则，不应因为只认词骨架反复到期而永久不出现。

当前当天已有两条或存在未答 issue 时，保留原计划及题目，交由现有提交流程继续；改动只对之后启动的日计划生效，不能在恢复时改 word_id、覆盖 issue 或伪造另一身份的证据。若产品一定要求已开启当天也去重，则需要另设计持久可恢复的“因同组暂缓”状态，保证迟到提交和用户体验；不可直接把条目置 done。

测试矩阵：新词两条同范围只有一个席位且补满上限；两个到期/一个到期一个新/仅一条在范围/缺映射/不同设备 ID；V2、V3 预览与启动结果一致；连续跨日各成员依公平规则出现，反复错、暂缓和切换 Unit 不饥饿；已启动当天和已发未答 issue 升级后仍原样可答、重复提交幂等；未选成员 cards/events/due/学习状态不发生改变；保留两者的历史记录及单独查看能力；桌面和离线对同一输入给同结果。统计和 backlog 应单独定义为“待学习身份数”还是“去重后的当日席位数”，不能在修改选择后沿用原 `due.length-limit` 而误报。
