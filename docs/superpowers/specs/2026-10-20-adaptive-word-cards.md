# 专注卡片与自适应单词本

## 同日反馈修订：一次独立通过（当前规则）

用户实测后明确取消每词三遍和九题最低量。当前每词每天一种题型，三型从开头混排，独立答对一次即结束该词当天任务；错误/辅助后移到队尾，不再固定分钟等待。汉译英与听写均为字母横线；成功反馈只有“答对了 👍”，单词本状态留在词页和单词本。

用户确认首次通过记熟悉，跨天验证后记掌握：三个不同无错无辅助日且覆盖三型再晋级；任一错/辅助后重新积累。已掌握一错/两错降级仍保留，日内补对不冲销错误。首次/错词次日、第三天与FSRS长期安排保留。

旧当天计划按policy_version幂等升级，使用最近已保存结果决定是否已通过；保留名单、日志、原结果和错误，关闭已完成词的过时未答题。原暂缓词若之前已独立通过则转完成，否则继续暂缓。历史日期不改写。真实开发库升级前重新做SQLite备份；交互验收仍用隔离库。

## 以下为初版设计历史（重复次数与分钟冷却已被上节替代）


用户已批准前述设计并要求按 Codex 定接口/核心逻辑、本地 Coder 实现有界任务、Codex 验收的流程执行。本轮在 feat/adaptive-word-cards 开发，不自动合并推送。

- 唯一主入口“开始背单词”。每天上海日期固定最多40个不同词，先遗忘风险/逾期复习，再补新词；新词约核心7:二级3、易4:中4:难2，缺组回填，不牺牲到期词凑比例。难度冷启动取词形特征，后续实际错误优先。
- 首次学习三种卡片：英译汉选义、汉译英拼写、听写。每种连续正确3次，至少9题；同词穿插，错误短时重测。已掌握复习先测最弱或最久未测题型，失败升级为该题型3次补练。熟悉/不熟跨天检查覆盖三种题型。
- 专注卡片沿用批准的精简样稿：不显示次数/三条进度/流程说明；听写按字母显示横线，保留空格、撇号、连字符；右上角“学习该词”打开词页，返回保持原题。看过讲解记为辅助，不算无辅助首答通过。音频缺失可暂缓，不能冒算答对。
- 四个互斥动态单词本：生词、 不熟、熟悉、已掌握。首次9题无错无辅助完成可掌握；错1次完成为熟悉，日累计错2次保持不熟。已掌握错1次立即熟悉、同日错2次不熟。后续不熟无错完成升熟悉，熟悉无错三型通过升掌握；同日补练不冲销日错误。
- 每型独立FSRS（约90%默认目标），同日正确后约5/15分钟、错误约3分钟再安排（与其他词穿插）；首次完成次日验证，错词次日与第3天优先，之后随FSRS调整。状态分类与到期时间独立，未做题不伪造记录，不把短时9次等同跨天稳定。
- 增量表保存每日名单、目标/连续正确、题目、幂等答案和词状态；保留旧cards/review_logs，真实答题继续写FSRS和日志。旧记录按原状态保守映射，GET不迁移进度/创建任务。POST开始才固定今日名单，重复开始不换名单；跨日未完词优先。小词库可少于40。
- 队列暂时无到期题返回waiting与时间，不判今日已完成；未完/暂缓项明确区分。答案由服务端按题目判定，事务保存，answerId冲突拒绝，网络重试不重复计分。过午夜旧题拒绝，已存重试仍返回原结果。
- API /api/learning/today, /start, /next, /answer, /consult, /defer, /books。正式页面切到新链路；旧API继续兼容旧记录和回归测试。首页/词页/词表/进度对新词状态采用同一映射，不改释义/内容/凭据。
- 本轮只修改开发库，启用前库外备份；不访问生产库、不重置既有日志、不调用云模型。先写失败测试，再分块实现；最后全量类型/测试/构建、独立审查、桌面/手机浏览器验收。

依据：艾宾浩斯相关研究 https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0120644；个体化调度 https://github.com/open-spaced-repetition/awesome-fsrs/wiki/ABC-of-FSRS。分钟数及配比属于本应用产品起始规则，不宣称是遗忘曲线的唯一标准。
